# CompelOS qualification engine

The local qualification pipeline is SerpAPI Finder → PostgreSQL CRM/queue → the owner's rendered LinkedIn account → bounded public website research → deterministic qualification → PostgreSQL CRM. The dashboard is Next.js. `worker.cjs` hosts one persistent agent in `src/lib/compel-agent.cjs`; the former supervisor script is only a compatibility entry point.

## Non-negotiable rules

- The sole LinkedIn usage limit is unique person profiles per account per local day, using the existing `daily_limit` field and `DEFAULT_DAILY_SCRAPE_LIMIT`. Reservation is atomic in PostgreSQL immediately before navigation. Cached reads, identity/session checks and same-account same-day retries are free. Never introduce permits, hourly/rolling caps, per-kind budgets, minimum gaps, schedules, cooldowns, jitter or throttle sleeps. Per-kind counts are statistics only.
- Stop an account on LinkedIn/LICDN HTTP 401/403/429/999, login/authwall/checkpoint/challenge, a security warning, or mismatched account identity. Preserve the exact reason until the human reviews the account. A settings save, process restart or stale callback cannot clear a hold. Manual sign-in alone confirms the intended member and leaves processing paused.
- Retain Puppeteer, manual sign-in, persistent account profiles and rendered-page reading. No passwords, private LinkedIn endpoints, stealth/proxy/fingerprint workarounds or browser-library migration. Ask the user before changing browser libraries.
- PostgreSQL is the only runtime queue and state store. Keep owner-fenced leases, checkpoints, canonical-profile duplicate protection and suppression/contact-history guarantees. No Redis, BullMQ, Docker or service split. Local PID/launch/browser-ownership files are OS diagnostics, never an alternate queue.
- Treat an 8 GB Windows machine as a hard resource constraint. Default to one LinkedIn browser/tab, two public research tasks, three HTTP requests and a bounded six-item result/checkpoint save queue. Public rendering uses a separate short-lived headless Chrome. Recycle/idle-close Chrome automatically while retaining sign-in and intent.
- Recover a stale owner only after its PID is confirmed dead and its heartbeat expires, or after a verifiable explicit release. Unknown ownership must produce a useful failure; never erase an unverified/live Chrome lock or user profile.
- Followers must be strictly greater than `MIN_FOLLOWERS` (default 1000). Read raw text and parsed count from the already loaded profile, immediately after identity and before activity/contact/website work. Keep connections separate. At/below threshold → REJECTED/FOLLOWERS_BELOW_MIN; absent/unparseable → REVIEW. Never guess from connections. Store the applied threshold with the evidence. Legacy qualified records stay follower-unchecked until explicitly selected for recheck; never automatically requeue them.
- Once a lead is decided, skip remaining page actions/crawls. Resume partial work from PostgreSQL checkpoints. A website/CRM failure must not reread LinkedIn. Nonretryable failures are terminal REVIEW with evidence, not a retry loop.
- Worker launch/control features are unavailable on Vercel. Keep the local-host/admin and same-origin checks. Never inspect, edit, stage or commit real secrets or `.env` files. Runtime configuration loading is allowed; `.env.example` may document requested public variable names/defaults.
- Ask before deleting user data or destructive schema changes. Additive migrations are allowed. Do not reset or include unrelated work in a commit.

## Verification and documentation

Read [engine-v2.md](docs/engine-v2.md), [engine-audit.md](docs/engine-audit.md) and [engine-measurements.md](docs/engine-measurements.md). Before behavior changes, preserve up to 50 already-decided CRM records with reasons/evidence. Replay stored evidence after every phase without visiting LinkedIn; report every decision delta and distinguish follower-rule changes from any other drift. Keep private snapshots and full per-lead reports under ignored `data/engine-v2/`; PostgreSQL stores benchmark manifests and reports.

Work and commit phase by phase. Validate the affected behavior with meaningful tests. Engine checks: `node --test --test-concurrency=1 tests/workers/*.test.cjs tests/prospects/*.test.cjs tests/coach-prospecting/*.test.cjs`; CRM checks: `npm run test:crm`; types: `npx tsc --noEmit`; lint: `npm run lint`. Browser tests use local fixtures, never live LinkedIn. Run authorized live measurements separately from tests/builds, reuse the same 30 profile URLs, preserve review holds and disclose failed/partial measurements. Do not infer performance gains from an uncompleted batch.
